# T-013 백엔드 프로젝트 골격
- 담당: Backend
- 페이즈: 1
- 선행: T-003 (OpenAPI 1차 확정)
- 병렬 가능: T-011(Infra), T-014(Frontend)

## 목표
Spring Boot 프로젝트 골격을 만들고, 헬스 엔드포인트·에러 포맷·DB 마이그레이션·arm64 Docker 이미지까지 동작하게 한다.

## 입력 문서
- AGENTS.md
- docs/03-backend-spec.md, docs/06-security.md §4, §6
- docs/02-infrastructure.md §6~7
- api/openapi.yaml (`/health`, `Problem` 스키마)

## 범위
- In:
  - Gradle(Kotlin DSL) 프로젝트, Java 21, Spring Boot 3.x, 가상 스레드 활성화
  - 패키지 골격(`docs/03` §2), `common`의 Problem Details 전역 예외 처리
  - `GET /api/v1/health` (인증 없음, `{status: UP}`만)
  - Flyway V1: `docs/03` §3 테이블 중 `users`, `managed_service`, `service_state`, `health_check_result`, `audit_log` 기본 스키마
  - SQLite(WAL) 설정, `Clock` 빈
  - 멀티스테이지 Dockerfile (JRE 21, non-root, layered jar, read-only FS 호환)
  - Spotless, 기본 단위/슬라이스 테스트
- Out: 인증, 서비스 CRUD, Docker 연동 (Phase 2~)

## 산출물
- `backend/` 전체 (build.gradle.kts, src/, Dockerfile, README 실행법)

## 완료 기준 (DoD)
- [ ] `./gradlew build` 통과 (테스트·Spotless 포함)
- [ ] `/api/v1/health` 응답이 `openapi.yaml`과 일치 (계약 테스트)
- [ ] 임의의 에러가 `application/problem+json`으로 반환됨 (스택 트레이스 미노출)
- [ ] `docker buildx build --platform linux/arm64`가 성공하고 이미지는 non-root로 실행됨
- [ ] 컨테이너 유휴 RSS 측정값 첨부 (목표 ≤ 250MB, `-Xmx256m -XX:+UseSerialGC`)
- [ ] 불필요한 스타터 없음, 추가 의존성 사유 기록
- [ ] 문서와 구현 일치, 소유 경로 위반 없음
