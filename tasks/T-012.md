# T-012 Tailscale 설치 및 Serve 구성
- 담당: Infra
- 페이즈: 1
- 선행: T-011
- 병렬 가능: T-013, T-014

## 목표
Tailscale을 설치하고 **Serve만** 활성화해 tailnet 기기에서 HTTPS로 Caddy(private)에 접속하게 한다. Funnel은 이 작업에서 켜지 않는다 (T-052).

## 입력 문서
- AGENTS.md
- docs/01-architecture.md §2
- docs/02-infrastructure.md §5
- docs/06-security.md §2, §8
- docs/adr/README.md (ADR-0007, ADR-0009)

## 범위
- In:
  - Tailscale 설치 절차 스크립트/문서 (공식 apt 저장소)
  - `infra/tailscale/serve.json`: 443 → `127.0.0.1:8080`(private). Vaultwarden용 포트는 T-015에서 추가
  - **Serve가 허용하는 HTTPS 포트 범위를 실측**하고 결과를 `docs/09`·ADR-0009에 반영 제안
  - `infra/tailscale/acl.example.json`: 최소 권한 ACL 예시, Funnel 속성은 주석으로 설명만(적용하지 않음)
  - 서비스별 포트 할당표 초안 (`infra/tailscale/PORTS.md`)
- Out: Funnel 활성화, 공개 사이트 블록 검증(T-052)

## 산출물
- `infra/tailscale/{serve.json,acl.example.json,PORTS.md}`, `infra/scripts/tailscale-setup.sh`

## 완료 기준 (DoD)
- [ ] tailnet 내 다른 기기에서 `https://<node>.<tailnet>.ts.net/` 접속 성공 (Caddy 응답)
- [ ] 비-tailnet 기기/인터넷에서 접속 불가 (`tailscale funnel status`가 비활성)
- [ ] `tailscale serve status` 출력 첨부
- [ ] 포트 범위 실측 결과 보고
- [ ] 인증 키/토큰이 저장소·로그에 없음

## 수동 단계 🙋
- `tailscale up` 로그인 인증
- 관리 콘솔: MagicDNS, HTTPS 인증서 활성화
- ACL 적용 (Funnel 허용은 T-052에서)
