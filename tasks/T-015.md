# T-015 Vaultwarden + Uptime Kuma (tailnet 전용)
- 담당: Infra
- 페이즈: 1
- 선행: T-011, T-012
- 병렬 가능: T-013, T-014

## 목표
기성 서비스 Vaultwarden과 Uptime Kuma를 Compose에 추가하고 tailnet에서만 접속되게 한다.

## 입력 문서
- AGENTS.md
- docs/02-infrastructure.md §3, §6, §8, §11
- docs/06-security.md §2, §6, §7
- infra/tailscale/PORTS.md (T-012 산출물)

## 범위
- In:
  - `infra/compose/services/{vaultwarden,uptime-kuma}.yaml` (또는 compose.yaml 병합): 버전 고정, `mem_limit`(64MB/256MB), 데이터 볼륨 `/srv/selfhost/{vaultwarden,kuma}`
  - Vaultwarden: `SIGNUPS_ALLOWED=false`(최초 계정 생성 후), `ADMIN_TOKEN` 해시 사용 또는 admin 비활성, HTTPS(Serve) 전제, 도메인 설정
  - Uptime Kuma: 체크 간격 ≥ 60s, 이력 보존 7일 (`docs/02` §11)
  - `serve.json`에 해당 서비스 포트 매핑 추가 (Funnel 제외)
- Out: 공개 노출, 백업(T-044)

## 산출물
- 위 compose 조각, `serve.json` 갱신, `infra/README.md` 서비스 접속 표

## 완료 기준 (DoD)
- [ ] tailnet에서 각 서비스 HTTPS 접속, 인터넷에서는 접속 불가
- [ ] Vaultwarden 가입 비활성 확인, 관리자 토큰이 저장소에 없음
- [ ] 컨테이너 재생성 후 데이터 유지 (볼륨 확인)
- [ ] `check-resources.sh`: 전체 메모리 예산 이내, 쓰기량 측정값 첨부
- [ ] `compose config` 유효, `latest` 없음
